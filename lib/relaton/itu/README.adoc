= Relaton::Itu: retrieve ITU Standards for bibliographic use using the BibliographicItem model

RelatonItu is a Ruby gem that implements the https://github.com/metanorma/metanorma-model-iso#iso-bibliographic-item[IsoBibliographicItem model].

== Usage

=== Search for a standard using keywords

[source,ruby]
----
require 'relaton/itu'
=> true

hit_collection = Relaton::Itu::Bibliography.search("ITU-T L.163")
=> <Relaton::Itu::HitCollection:0x00000000001700 @ref=ITU-T L.163 @fetched=false>

item = hit_collection[1].item
=> #<Relaton::Itu::ItemData:0x000000012541b8f8
 ...
----

=== Typed source links

Each ITU document has `src` type link and optional `obp` and `word` link types.

[source,ruby]
----
item.source[0].type
=> "src"

item.source[0].content
=> "https://handle.itu.int/11.1002/1000/14547"
----

=== Fetch data

The method `Relaton::Itu::DataFetcher.fetch("itu-t", output: "data", format: "yaml")` harvests every ITU-T recommendation edition (from the `mws/api/recommendations/searchRecs` index) and saves the documents to the `./data` folder in YAML format.
Arguments:

- `source` - source name (`itu-t`).
- `output` - folder to save documents (default `data`).
- `format` - the format in which the documents are saved. Possible formats are: `yaml`, `xml`, `bibxxml` (default `yaml`).

[source,ruby]
----
Relaton::Itu::DataFetcher.fetch "itu-t", output: "dir", format: "xml"
Started at: 2026-08-12 09:21:16 -0400
Stopped at: 2026-08-12 11:27:45 -0400
Done in: 7589 sec.
=> nil
----

NOTE: **ITU-R harvesting is disabled.** ITU decommissioned the RunSearch bulk-enumeration endpoint the ITU-R crawler paged through, so `fetch("itu-r")` (and the argument-less `fetch`) raises a `Relaton::RequestError` pointing at https://github.com/relaton/relaton/issues/75[issue #75] instead of rebuilding an empty dataset. The published ITU-R records are preserved in https://github.com/relaton/relaton-data-itu[relaton-data-itu] and re-indexed on each crawl via `DataFetcher#index_files("data/itu-r-*.yaml")`; runtime ITU-R lookups are unaffected.

`Relaton::Itu::DataCrawlerR` prototypes a replacement crawl over ITU's still-server-rendered `/pub` + `/rec` pages (Recommendations and Reports), and `Relaton::Itu::DataMergeR` merges what it finds into the existing dataset without ever rewriting a published date. Neither is wired into `fetch` — reaching them takes an explicit `require`:

[source,ruby]
----
require "relaton/itu/data_crawler_r"
require "relaton/itu/data_merge_r"

fetcher = Relaton::Itu::DataFetcher.new "data", "yaml"
crawler = Relaton::Itu::DataCrawlerR.new
items = crawler.harvest("BO", only: %w[R-REC-BO.1130 R-REC-BO.1212]) +
        crawler.harvest("BO", family: "R-REP", only: %w[R-REP-BO.1227 R-REP-BO.2006])
Relaton::Itu::DataMergeR.write_all items, fetcher
=> {added: 0, backfilled: 4, unchanged: 6, skipped: 0, collisions: []}
----

Those counts are from that ten-record run against the published dataset: four records gained the PDF link they were missing, six were left byte-identical, and no publication date was touched. Drop `only:` to harvest a whole series (54 recommendation documents / 82 editions for `BO`).

=== Logging

RelatonItu uses the relaton-logger gem for logging. By default, it logs to STDOUT. To change the log levels and add other loggers, read the https://github.com/relaton/relaton-logger#usage[relaton-logger] documentation.

== Development

After checking out the repo, run `bin/setup` to install dependencies. Then, run `rake spec` to run the tests. You can also run `bin/console` for an interactive prompt that will allow you to experiment.

The index test fixture (used by tests) is a trimmed copy of the published pubid-structured `index-v2.zip` (rows are `_type: pubid:itu:…` hashes) from the `main` branch of the combined https://github.com/relaton/relaton-data-itu[relaton-data-itu] repository, kept at `spec/fixtures/index-v2.zip`. Refresh it with the regeneration snippet in `lib/relaton/itu/CLAUDE.md` (it must deserialize under the pinned pubid).

To install this gem onto your local machine, run `bundle exec rake install`. To release a new version, update the version number in `version.rb`, and then run `bundle exec rake release`, which will create a git tag for the version, push git commits and tags, and push the `.gem` file to [rubygems.org](https://rubygems.org).
