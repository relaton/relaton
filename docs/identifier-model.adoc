= The Relaton identifier model
v1.0 (2026-10-20)

This document specifies Relaton's identifier semantics formally: the component
model, canonicalization, equivalence, and matching. It is the normative
reference for pubid grammars and every flavor's consumer logic; code that
deviates is a bug, and behavior not specified here is not yet a contract.

The acceptance tests for this model are the corpus property suite
(spec/corpus/): the invariants below run over every flavor's **full published
corpus**, not fixtures.

== 1. The component model

Every identifier in the standards domain decomposes into named components:

|===
| Component | Kinds | Notes

| publisher / copublisher | one or many | The SDO(s) that issued the document. Joint identifiers (`ISO/IEC`, `IEEE/ASTM`) hold a publisher list whose **printed order is identity**.

| series / type | one | The SDO's series label (`ISO`, `FIPS`, `TS`, `TR`, `REC`, `P`).

| number / code | one | The document's number within its series. Free-form tokens keep leading zeros (`0001`) and sub-numbers (`0812-1`) **verbatim**; they are never numerically normalized.

| part / subpart | zero or more | Hierarchical subdivision. A nil part and an absent part are different values only where the SDO prints them differently (space vs hyphen is identity in EVS; a name-part is not a numbered part in OMG).

| edition / version / revision | zero or one | The document's own version discriminator. For named-version SDOs (OMG) the version plays the role edition plays elsewhere; for stage-based SDOs the stage does.

| stage / iteration | zero or one | The publication stage (`fpd`, `ipd`, `DIS`, `WD`, `PRD`...). A stage-bearing identifier and its stage-less base name **different records of one family**.

| year / date | zero or one | Publication year or date. Carrier of the "other years" resolution message in the year-strict flavors.

| language / script | zero or one | Where the SDO publishes per-language editions.

| update / corrigendum / amendment | zero or more | In-place updates that are records of their own.
|===

Two representations exist for every identifier: the **structured form** (the
component object) and the **printed form** (the citation string). The model's
laws:

[quote]
Law 0 (structured fidelity). Every row of a published index deserializes
through its own pubid class, and the structure round-trips:
`from_hash(to_hash(x)) == x`. A published row the grammar cannot read is a
corpus defect, never a silently skipped row.

Law 1 (fidelity). The two representations are the same identifier:
`render(parse(printed)) == printed` (1a) and `parse(render(x)) == x`
structurally (1b).

== 2. Canonicalization

A printed form may have several **spellings** (separators, case, publisher
prefixes, glued labels). Canonicalization maps every spelling to one printed
form, per SDO rules:

* One separator rendering per component boundary (pubid renders one separator;
  both spellings of an OMG part name the same document).
* Publisher tokens print in the corpus order; a bare series+number spelling
  resolves to the SDO's default publisher.
* Case normalization applies only where the SDO prints one case (acronyms are
  verbatim: `EDMC-FIBO/BE`, `smartant`, `VSIPL++` are valid publishers' forms).

[quote]
Law 2 (canonical idempotence). Canonicalization is a function:
`canonical(parse(canonical(printed))) == canonical(printed)`. Excluding an
absent component changes nothing: `x.exclude(*absent(x)) == x`.

== 3. Equivalence classes

Three equivalence relations over identifiers, all declared as **data**, not
per-flavor code:

=== 3.1 Joint publication

Two identifiers are joint-equivalent when they carry the same document through
different publisher orderings (`ISO/IEC 14515-1` ~ `IEC/ISO ...` where an SDO
prints it). Equivalence tables hold the direction each corpus prints; the
resolver consults the table, and co-publisher fallback (relaton#205) walks it.

=== 3.2 Adoption

An adoption chain links a document to its national/regional adoptions
(`ISO 1234` -> `EN ISO 1234` -> `BS EN ISO 1234` -> national-language
editions). Chains are directed edges in the citation graph, resolvable
end-to-end (`#root` recurses the chain). The adopted identifier's components
are the **adopting** SDO's series/number with the base's carried through.

=== 3.3 Variant

Variant spellings (separator/case/glue differences, prefixed forms such as
`IETF RFC 7200` for `RFC 7200`) map to one canonical identifier. Variants are
declared per family in the tables; unlisted spellings are parse errors.

[quote]
Law 3 (equivalence is data). Every joint, adoption, or variant relation used
in resolution appears in an equivalence table under docs/identifier-model/ or
the flavor's data; a resolution that consults undeclared equivalence is a bug.

== 4. Matching (the reference-vs-record relation)

Resolution matches a **reference** (what a caller wrote) against **records**
(what the corpus holds). The relation is pubid's SubsetMatch (`===`):

* The reference is the receiver; a component the reference leaves nil or empty
  matches any record value (wildcard).
* A component the reference states must match the record's value exactly —
  **except** where the flavor declares `subset_strict` for that component,
  when a nil on either side is a mismatch instead of a wildcard (ECMA `part`,
  3GPP `suffix`, CCSDS `language`...).
* Classes must be identical: an amendment never matches its base.

[quote]
Law 4 (matching symmetry modulo omission). Within a corpus bucket (same root
number), for any pair a, b: if `a === b` and `b === a` then `a` and `b` render
identically. Asymmetric `===` is legal and meaningful only when one side omits
components the other states. The corpus suite tests the contrapositive over a
deterministic sample of same-root pairs: two identifiers that render
differently never match both ways.

== 5. Per-family conformance

Each SDO family declares, in docs/identifier-model/<family>.adoc (seeded from
the flavor CLAUDE.mds): its component inventory, subset_strict components,
canonicalization rules, known grammar edges with pinned specs, and its corpus
property-suite membership. A family is conformant when the corpus suite runs
green over its full published corpus.

== 6. The corpus property suite

spec/corpus/ runs Laws 0, 1, 2 and 4 over each flavor's published index:

[quote]
.Laws under test
----
from_hash(to_hash(id)) == id                     # Law 0
render(parse(printed)) == printed                # Law 1a
parse(render(id)) == id (structurally)           # Law 1b
id.exclude(*absent(id)) == id                    # Law 2
(a === b && b === a) -> renders equal            # Law 4
----

Failures are filed per family (pubid for grammar, the flavor for consumer
logic) and the family drops out of "conformant" until fixed. A failure is
tracked in `spec/corpus/known_failures/<family>-<law>.txt`; the prose entry is
the tracking record, and an unlisted failure is copied in and fails the run.
Run it locally with `rake spec:corpus` (`CORPUS=nist,oasis` narrows the set);
the scheduled `corpus` workflow runs the same task per flavor.

== 7. Per-family inventory

Every family shares the base component set:

`number`, `part`, `subpart`, `stage_iteration`, `date`, `edition`, `languages`,
`publisher`, `copublishers`, `type`, `stage`, `locality`, `typed_stage`.

Each section below adds the family's own components, names its `subset_strict`
components (a nil there is "this document has none", not a wildcard), and notes
the grammar edges that have a pinned spec. Families with no published
`relaton-data-*` index yet (BSI, CEN/CENELEC, EVS, GB, UN, ...) join this
inventory when a corpus lands; their identifier behavior is still governed by
sections 1–4.

=== 3GPP
`Pubid::Tgpp::Identifier` adds `suffix`, `parts`, `release`, `version`;
`suffix` and `parts` are strict. Hyphenated parts are a pinned edge.

=== Adobe
`Pubid::Adobe::Identifier` adds no components beyond the base set.

=== BIPM
Adds `group`, `type_code`, `year`, `language`, `form`, `issue`, `article`,
`version`, `years`, `variant`, `mep_code`, `report_code`, `guide_kind`,
`appendix`, `annex`.

=== CalConnect
Adds `series`, which is strict.

=== CCSDS
Adds `suffix` and `language`; both are strict.

=== CIE
Adds `style` (the bundle/consolidated style).

=== EASC
Adds `series`, `variant`, `year`.

=== ECMA
Adds `volume`; `part` is strict.

=== ETSI
Adds `version` and its edition/version list.

=== GOST
Adds `copublisher`, `subtype`, `year`; `copublisher` is strict.

=== IALA
Adds `language`.

=== IANA
Adds `sub_registry` (the nested registry path).

=== IEC
No components beyond the base set; consolidated identifiers carry the
supplement layer through the base `stage`/`date` components.

=== IEEE
Adds the draft/revision machinery: `copublisher`, `year`, `draft_status`,
`draft`, `revision`, `rev_sep`, `rev_bare`, `month`, `month_glued`, `day`,
`redline`, `amendments`, `corrigenda`, `revision_of`, `incorporates`,
`supersedes`, `supplement_to`, `iso_identifier`, `parenthetical_content`,
`note`, `adoption`, `amendment_to`, `edition_month`, `space_before_draft`,
`relationships`, `nickname`, `interpretation`, `ashrae_number`, `ashrae_year`,
`crossref`, `reaffirmed`. The `D=` designator, `Rev<n>`, redline and adoption
forms each have their own pinned spec.

=== IETF
No components beyond the base set; drafts are distinguished by
`stage_iteration`.

=== IHO
Adds `appendix`, `annex`, `supplement`, `version`. The leading type letter
(S/P/M/B/C) selects the concrete identifier class; the published index is
`index-v3` because v2 predates the polymorphic `_type` rows.

=== ISO
No components beyond the base set. Deleted/substage-98 rows are not published.

=== ITU
Adds `sector`, `series`, `code`, `language`, `version`, `series_word`,
`series_dash`, `attachment`, `range_end`, `common_text_twin`; subclasses add
`base`, `number_glued`, `slash_joined`, `technical`, `material`. Slash-joined
corrigenda/amendments and common-text twins are pinned edges.

=== JCGM
No components beyond the base set.

=== JIS
Adds `series`, `parts`, `year`, `language`, `reaffirmed`, `symbol`.

=== NIST
Adds the widest set: `series`, `subseries`, `volume`, `version_component`,
`update_component`, `translation_component`, `issue_number`, `parsed_format`,
`publisher_was_parsed`, `parts`, `revision_year`, `revision_month`,
`edition_year`, `version`, `update`, `year`, `month`, `first_number`,
`second_number`, `update_number`, `update_year`, `addendum`,
`addendum_number`, `supplement`, `errata`, `index`, `insert`, `section`,
`appendix`, `translation`, `draft`, `draft_number`, plus the date/range
helpers. Stage suffixes (`ipd`, `2pd`, ...) resolve to their own records; the
`nA`/`nB` annex suffixes (pubid#555) and the `indx` normalization (pubid#557)
are the open edges.

=== OASIS
Adds `original`, `version`, `label`.

=== OGC
Adds `year`, `revision`. Draft types (`CAN`, `DP-Draft`, `RFC`) carry stage
`draft`.

=== OIML
No base-class components beyond the base set; subclasses add the annex letter
and supplement language, with `language`, `letter`, `part`, `subpart` and
`suffix` strict.

=== OMG
Adds `acronym`, `version`. Slash-bearing part names and the glued beta label
are pinned edges (pubid#548); the acronym catalogue has a spec of its own.

=== Plateau
Adds `annex`, which is strict.

=== W3C
No components beyond the base set; maturity stage lives in `stage`.

=== XSF
No components beyond the base set.
